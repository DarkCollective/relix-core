# Code of Conduct

Relix adopts the
[**Contributor Covenant, version 2.1**](https://www.contributor-covenant.org/version/2/1/code_of_conduct/)
as its code of conduct. It sets out the standards expected of everyone who takes
part in the project, the behaviour that is not acceptable, and the consequences
maintainers may apply. This page adds only what the Covenant leaves to each
project: where it applies, how to report a problem, and what happens to a report.

## Where it applies

In every project space — this repository's issues, pull requests, discussions and
reviews, and any other channel run for the project — and when someone is
representing the project elsewhere.

## Reporting a problem

**[Report an incident using this form](https://docs.google.com/forms/d/e/1FAIpQLSd5z5m517BWo0An9nS6ZAnAoVvM5UwgNZgMSviayUo7OWGOkg/viewform).**
Only the project maintainers can read what you submit. You do not need a Google
account, and **you may report anonymously** — your name and email are optional,
and an email is only needed if you would like a reply.

Please describe what happened, who was involved, and link any issues, pull
requests or other pages that give context. You do not need to be sure a rule was
broken to report something.

To flag a single comment, issue or pull request, you can also use GitHub's
*Report content* option on it.

**Security vulnerabilities are not conduct reports.** Report those as described in
[`SECURITY.md`](SECURITY.md).

## What happens next

- The maintainers review every report, and reply if you left an email.
- Reports are kept confidential. The reporter's identity is not shared with the
  person reported without the reporter's consent.
- A maintainer involved in a report takes no part in handling it.
- Any action taken follows the enforcement guidelines in the Covenant, from a
  private warning up to a permanent ban, according to the seriousness of what
  happened.
